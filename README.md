# shadcn-vite-starter

A React starter with the stack already wired: Vite, TypeScript, TanStack Router, Query and Form, and shadcn/ui on Base UI. It ships a page built from six free [7Ovr](https://7ovr.com) blocks and a working example of the whole data flow, so you can start on the product instead of the setup.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https://github.com/7ovr/shadcn-vite-starter&project-name=shadcn-vite-starter&repository-name=shadcn-vite-starter)

## Quick start

You need Node 20.19 or newer and [pnpm](https://pnpm.io).

```bash
git clone https://github.com/7ovr/shadcn-vite-starter
cd shadcn-vite-starter
pnpm install
pnpm dev
```

Open http://localhost:5173.

## What is inside

| Layer      | Choice                                                         |
| ---------- | -------------------------------------------------------------- |
| Build      | Vite 8                                                         |
| UI         | React 19, shadcn/ui (`base-nova` style) on Base UI             |
| Styling    | Tailwind CSS v4 with CSS variable theme tokens, light and dark |
| Language   | TypeScript in strict mode                                      |
| Routing    | TanStack Router, file-based and code-split per route           |
| Data       | TanStack Query, wired into the router context                  |
| Forms      | TanStack Form with Zod validation                              |
| Tests      | Vitest and Testing Library                                     |
| Code style | ESLint and Prettier, run on staged files by Lefthook           |

## Project structure

```
src/
├── routes/               File-based routes (TanStack Router)
│   ├── __root.tsx        Layout, header and the not found page
│   ├── index.tsx         Home page, composed from 7Ovr blocks
│   └── waitlist.tsx      Router, Query and Form example
├── components/
│   ├── blocks/           Installed 7Ovr blocks, yours to edit
│   └── ui/               shadcn/ui components
├── features/waitlist/    The example feature: API, queries, schema, form
├── lib/                  Shared utilities and the query client
├── router.tsx            Router setup and type registration
├── routeTree.gen.ts      Generated by the router plugin, do not edit
└── index.css             Tailwind and the theme tokens
```

## Add blocks from 7Ovr

`components.json` already knows the 7Ovr registry. Install any free block by name:

```bash
pnpm dlx shadcn@latest add @7ovr/hero-2
```

The source lands in `src/components/blocks/`. Import it into a route:

```tsx
import HeroBlock from "@/components/blocks/hero-2"
```

Browse every block at [7ovr.com/blocks](https://7ovr.com/blocks).

### Pro blocks

The `@7ovr-pro` registry is configured too. Copy `.env.example` to `.env`, set `REGISTRY_TOKEN` to the token from your 7Ovr account, then install from the Pro namespace:

```bash
pnpm dlx shadcn@latest add @7ovr-pro/<name>
```

`.env` is ignored by git, so the token stays on your machine.

## The waitlist example

`/waitlist` shows the three TanStack libraries working together:

- the route loader fills the Query cache before the page renders,
- the form validates with Zod through TanStack Form,
- a mutation adds the signup and invalidates the list, which refetches.

The API in `src/features/waitlist/api.ts` is an in-memory stand-in. Replace those functions with `fetch` calls to your backend and the rest keeps working. To remove the example, delete `src/features/waitlist/` and `src/routes/waitlist.tsx`, and take the link out of `src/components/site-header.tsx`.

## Scripts

| Command           | What it does                                  |
| ----------------- | --------------------------------------------- |
| `pnpm dev`        | Start the dev server with the router devtools |
| `pnpm build`      | Typecheck, then build to `dist/`              |
| `pnpm preview`    | Serve the production build locally            |
| `pnpm test`       | Run the test suite once                       |
| `pnpm test:watch` | Run the tests in watch mode                   |
| `pnpm lint`       | Lint with ESLint                              |
| `pnpm typecheck`  | Typecheck with TypeScript                     |
| `pnpm format`     | Format with Prettier                          |

## Deploy

`pnpm build` writes a static site to `dist/`. Routing happens in the browser, so the host must serve `index.html` for every path:

- **Vercel**: handled by the included `vercel.json`. Use the button above.
- **Netlify**: add a `public/_redirects` file containing `/* /index.html 200`.
- **Anything else**: configure a fallback to `index.html`.

## Theme

Colours come from CSS variables in `src/index.css`, with a light and a dark set. Change them there and every component and block follows. Press `d` to toggle dark mode, or use the button in the header.
